XPM is an obscure image format which can\textquotesingle{}t seem to make up its mind whether it wants to be written in C code or not.

\href{https://en.wikipedia.org/wiki/X_PixMap}{\texttt{ https\+://en.\+wikipedia.\+org/wiki/\+X\+\_\+\+Pix\+Map}}

This might anger some but instead I decided to write my own image format, very similar to XPM2, which seems to be the better option between the 3 versions. The only difference is in the header which carries the file type, width, height, color count and finally color type aka \textquotesingle{}c\textquotesingle{} for RGBA8 or \textquotesingle{}m\textquotesingle{} for monochrome output.

The changes, in my opinion, very much simplify the XPM format into something literally anybody can use without much guessing as to what does what.

Additionally with the C style format, the idea is that you simply include it directly into the compilation of the program (since it\textquotesingle{}s just C).

As convenient as this is, I just find it hideous especially the XPM3 variant. By sticking to the XPM style format, conversion should be very easy and straightforward to this format however. Parses HEX color channel e.\+g\+: "{}0\+F"{}
